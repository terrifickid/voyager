# Plan — AI-assist mockups across three surfaces

## Goal

Add three scripted, register-aware mockups grounded in `ai.md`:
1. **Voyager Pay AI Assist** — intent parser, AI-scored Mostro nodes, anomaly guard
2. **In-browser Nostr AI client** — search, write, embed modes; the embed mode is a JS snippet a site owner can drop into any existing website that pulls in relevant Nostr products/services via local AI queries
3. **Unified `/projects/ai`** — tabbed showcase that combines the above two

Plus:
4. **Inject an AI Assist section** into the existing `/projects/voyager-pay` page
5. **Update `/projects` overview** with three new showcase cards

All mockups are scripted (no real model, no real relays, no new dependencies). Same `carnival-poster` register as the rest of the site.

## Components

All new components live in `voyager/src/lib/components/` and are register-aware (use `bg-[var(--register-card)]`, `text-[var(--register-text)]`, `text-[var(--register-muted)]`, etc., never hardcoded bone/ink). All `<Cta>`, `<SectionHeader>`, etc. take `register="carnival-poster"`.

### New components

**1. `PayAiAssistCard.svelte`** (used on `/projects/ai-pay`, `/projects/ai`, and `/projects/voyager-pay`)
- Input row: a chat-style text field with a `Send` button. Dropdown of 4 scripted example intents (chips above the input).
- Typed intent reveals the parsed JSON below the input in three columns: **Payee**, **Amount/Currency**, **Memo/Flag**. Stagger-revealed (scripted 600ms total).
- "Score Mostro nodes" button → reveals a ranked list of 3–4 fixture Mostro nodes with three small bar metrics each: rate, speed, reliability. The selected node is highlighted; below the list the AI surfaces the trade-off in plain English (e.g. "Node A: 0.30%, 2 min avg, 99% uptime — fastest this hour. Node B: 0.25%, 8 min avg — saves ~120 sats on a $50 trade.").
- "Anomaly guard" toggle (scripted on/off): when on, a payment that mismatches the user's fixture history triggers a yellow alert strip below the input: "This payment is 6× your usual outgoing amount, and Alice is a new counterparty. AI suggests a 5-second pause before signing." A `Sign anyway` and `Hold` pair of buttons. The sign action is a no-op that flips to a "Signed ✓" green chip.
- All transitions scripted with `setTimeout` and `await tick()`; no real timers leak between sessions (component-scoped `setTimeout` ids cleared on `onDestroy`).

**2. `NostrAiAgent.svelte`** (the parent component for `/projects/nostr-ai` and `/projects/ai`)
- Top bar: tabs for **Search · Write · Embed**
- Right side of top bar: a small relay-status pill row — three relay chips `wss://relay.bz`, `wss://relay.jm`, `wss://relay.lisbon.pt` each with a colored dot and a `connected / live` line. Dots animate between relays as the active query/relay changes (scripted).
- Below the bar: the active child component renders.

**3. `NostrAiSearch.svelte`**
- Two-column layout: left = the agent's natural-language input + reasoning trace, right = the relay result panel.
- Input: a text field with 3 example queries as chips ("Find a Grenada carpenter with strong zaps", "Barbados live music this Friday", "Cheapest JMD ramp today").
- On submit: scripted trace fills in over ~3s — shows the parsed `filters` (kinds, authors, tags), the parallel `REQ` JSON shape, the relay that returned first, then the local ranking algorithm's output (`graphDistance: 2`, `zaps: 12.4k`, `contentMatch: 0.81`). Top 3 ranked results render as cards with pubkey, reputation bar, last-active.
- A "Explain" hover reveals the prompt the local model would have used (just the prompt text rendered in a popover — no actual inference).

**4. `NostrAiWrite.svelte`**
- Two modes via inner tabs: **Compose listing** and **Sign & publish**.
- Compose listing: a form with title, summary, price (sats + fiat), kind selector (`30402 marketplace listing`, `31923 calendar event`, `1 short note`, `30018 long-form`), tags, location. Below: a live-preview pane of the JSON event (Nostr event shape, with placeholder `id`, `sig`).
- Sign & publish: shows the event JSON, then the "signing" animation (scripted 1.5s) which replaces `sig` with a deterministic mock signature, then "publishing" sends a scripted `OK` message back from each of the 3 relays (with a fake 600–900ms delay each, displayed as they arrive).
- A "Copy event JSON" button and a "Copy cURL to publish manually" block (for users who want to see what a real publish looks like).

**5. `NostrAiEmbed.svelte`**
- Left side: a JS snippet code block (`<script src="..."></script>` with the rendered HTML showing the script tag a site owner would paste). Includes a one-line config block: `data-relays="relay.bz,relay.jm,relay.lisbon.pt"` and `data-query="caribbean goods"` and `data-kind="30402"`.
- Right side: a mocked page (an "Any existing site" example — a fake HTML page with placeholder content like a hotel page). Below it: a panel that shows the live-injected cards the embed would render — 3 product/service cards pulled from the fixture marketplace events, styled like a "Related from Caribbean sellers" rail.
- A "Copy snippet" button on the left. A "View rendered HTML" toggle on the right that shows the post-injection DOM as a code block.
- Footnote: "All inference happens in the visitor's browser. No telemetry leaves the device."

### Shared helper components

**6. `AiTraceStream.svelte`** — a small "agent reasoning" log component used by all three AI mockups. It accepts a list of trace lines `{ ts, kind: 'parse' | 'query' | 'score' | 'sign' | 'publish' | 'explain', text }` and animates them in with a 250ms typewriter cadence. Used by PayAiAssistCard, NostrAiSearch, NostrAiWrite.

**7. `RelayChip.svelte`** — single colored-dot pill for one relay. Takes `name`, `status` (`connecting | live | slow | timeout`). Used by NostrAiAgent top bar and NostrAiSearch trace.

## Risks & decisions

- **Reuse vs. duplicate**: the `PayAiAssistCard` is shared between `/projects/ai-pay`, `/projects/ai`, and the injection on `/projects/voyager-pay`. The `NostrAiAgent` is shared between `/projects/nostr-ai` and `/projects/ai`. All shared components must take a `register` prop and a `variant` prop.
- **Scripted fidelity**: Per user choice — scripted interactions with `setTimeout`. No real model runs. Each scripted delay must be cleared on component destroy to avoid leaking timers across SPA route changes.
- **Markdown in JSON**: `aiMarketplace.json` will contain `summary` and `notes` strings with possible newlines. Use `\n` literals or split into arrays — pick one and document it.
- **Color scheme**: continue using `carnival-poster` site-wide. All new components register-aware. No new register tokens required.
- **Accessibility**: tablist must use real `role="tablist" / role="tab" / role="tabpanel"` and arrow-key navigation (since we already have `TableOfContents.svelte`, consider extracting a `Tabs.svelte` helper, but only if it cleanly factors out — otherwise inline).
- **Header / footer scope**: out of scope by default. Confirm at execution time whether to surface `/projects/ai*` links globally.
- **Scripted delays**: keep ≤1.5s per step so the user does not feel the mockup stalling. Total scripted flow per tab ≤6s.
